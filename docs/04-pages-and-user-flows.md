# 04 — Pages and User Flows

**Status:** Draft sitemap; page names and roles may change.

## Public pages
- Home / landing page
- Search results
- Property details
- Login / registration
- About UniNest
- Contact/help
- Terms and privacy information

## Student pages (proposed)
- Student profile
- Saved properties (optional)
- Booking request/confirmation
- My bookings

## Owner pages (proposed)
- Owner dashboard
- Create/edit property listing
- Listing review status
- Booking requests
- Availability management (if included in MVP)

## Admin/operations pages (proposed)
- Verification review queue
- Listing details and review evidence
- Booking overview
- Reported listings/users (later if needed)

## Primary discovery flow
Home → Search by university/location → Apply filters → Review listing cards → Open property details → Choose next action.

## Booking flow — policy not yet decided
Property details → Select room/stay details → Review price and terms → Submit request or confirm booking → Receive status/next steps.

Do not assume instant confirmation, online payment, or owner approval until the booking policy is selected.

## Verification flow — policy not yet decided
Owner submits listing and evidence → Authorized reviewer checks information → Approve / reject / request changes → Listing is published or remains unpublished → Owner is notified.

## UX states required on key pages
- Loading
- Empty results
- Validation errors
- Network/server error
- Unauthorized/forbidden
- Pending review
- Success/confirmation

## Design deliverables
Create low-fidelity wireframes first. Make high-fidelity screens only after the main flows and content requirements have been reviewed.
